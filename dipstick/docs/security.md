# Security

Dipstick is a personal tool on your own machine with no network access. It controls a device that puts RF on its port. The threats below are mapped to the OWASP Top 10 (2025), each with its mitigation and the tests that guard it.

| ID | Threat | OWASP 2025 | Mitigation | Tests |
|---|---|---|---|---|
| T1 | Dipstick erases or overwrites the NanoVNA's saved calibration or settings (a bug, or a bad future change) | A06 Insecure Design | An allowlist of read-and-sweep commands (`version`, `info`, `sweep`, `scan`, `frequencies`, `data`), plus `cal` alone (status) and seven fixed steps that change only memory. Never `save`, `clearconfig`, `power` or `reset`. Calibration commands are sent only from the Calibrate tab's buttons. | `test_anything_off_the_allowlist_is_refused`, `test_other_cal_arguments_are_refused`, `test_saving_or_recalling_calibration_is_still_refused`, `test_calibrating_open_short_load_over_the_band` |
| T2 | Command injection: a value containing a carriage return ends one command and starts another (`7000000\rclearconfig`) | A05 Injection | Command arguments must be whole numbers; command names must be on the allowlist | `test_arguments_must_be_whole_numbers`, `test_a_command_name_cant_carry_a_second_command`, `test_other_cal_arguments_are_refused` |
| T3 | Dipstick opens the wrong serial port, such as a radio's CAT port, and sends it text | A06 Insecure Design | Opens only a port with the NanoVNA's USB ID (0483:5740) *and* a name saying NanoVNA (the ID alone is ST's generic one, shared by tinySAs, flight controllers and other STM32 gadgets), or a USB ID the person chose in the app's port picker (for 0483:5740 the device's name is remembered with it, so approving an original-firmware NanoVNA doesn't approve a tinySA; a plain 0483:5740 approval, as builds before 2026-11-17 saved, is ignored), or the port given with `--port`. A port matching the original firmware's generic name is only *mentioned* in the not-found message, never opened. Ports open with DTR and RTS low (many radio interfaces key PTT on one), and only an empty line is sent until the `ch>` prompt answers. | `test_never_picks_something_that_isnt_a_nanovna`, `test_original_firmware_is_not_guessed_but_named`, `test_no_original_firmware_hint_for_other_gadgets`, `test_approving_the_original_firmware_does_not_approve_a_tinysa`, `test_a_plain_approval_of_the_generic_st_id_is_ignored`, `test_two_nanovnas_ask_which`, `test_the_port_opens_with_dtr_and_rts_low` |
| T4 | A garbled, endless or hostile reply crashes the tool or shows wrong numbers | A10 Mishandling of Exceptional Conditions | 5 s timeout for silence and for the whole reply; replies and the startup drain capped at 64 KB; printable ASCII only; the echo must match the command; impossible readings refused | `test_silence_times_out`, `test_an_endless_reply_is_cut_off`, `test_a_reply_that_trickles_on_without_a_prompt_gives_up_on_time`, `test_sync_gives_up_on_a_nanovna_that_never_goes_quiet`, `test_garbled_bytes_are_refused`, `test_a_wrong_echo_means_out_of_step`, `test_impossible_measurements_are_refused` |
| T5 | A wide sweep goes out through an antenna, onto non-amateur frequencies | none (radio rules, 47 CFR 97.301) | Antenna sweeps are locked inside one amateur band. Wide sweeps (cable, balun tests, calibrating HF wide) run only after you confirm no antenna; the app's checkbox clears after every test, and Python accepts only a real `true`. | `test_sweeps_that_leave_a_band_are_refused`, `test_antenna_scans_stay_inside_one_band`, `test_refused_without_no_antenna_and_nothing_is_sent`, `test_*_refused_unless_no_antenna_is_exactly_true`, the page's no-antenna-box tests |
| T6 | A compromised or vulnerable dependency | A03 Software Supply Chain Failures | Pinned versions (each at least two weeks old); `pip-audit` in CI and on each OS's app build; Dependabot | CI |
| T7 | Another web page triggers a sweep through the app, or the app window is sent to another page (a dropped file, a dragged link) that then calls the NanoVNA | A01 Broken Access Control | No web server: the page loads from `file://` and calls Python through pywebview's bridge. Only named methods are exposed, and every call that reaches the NanoVNA first checks the window is still on Dipstick's own page (`is_app_page`). | `test_the_page_can_only_reach_public_methods`, `test_another_page_is_refused_and_never_connects`, `test_a_page_the_window_is_sent_to_cant_use_the_nanovna` (real window), the self-test on every CI build |
| T8 | Markup in a report or error runs as code in the app window (XSS) | A05 Injection | Reports and errors are set as text, never HTML; the SVG comes only from Dipstick's own plot code; the Content Security Policy allows only the page's own script and stylesheet. Accepted risk: `'unsafe-eval'`, which pywebview's bridge requires. | `test_report_text_is_shown_as_text_not_markup`, `test_the_pages_security_policy`, `test_window.py` |
| T9 | A tampered download, or your own sweep files bundled into a build | A03 Software Supply Chain Failures | Built only by GitHub Actions from a clean checkout; SHA-256 checksums; releases start as drafts; build attestations (`gh attestation verify`); the build bundles only the page's three files by name. Accepted risk: the builds aren't code-signed (Apple's program costs $99 a year). | Checksum step and `--self-test` in the app workflow; `gh attestation verify` passed on beta.4 and failed on a tampered copy (2026-11-16) |

No secrets: nothing needs a key or password, so there's no `.env`.
